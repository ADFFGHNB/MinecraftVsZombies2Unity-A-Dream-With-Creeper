## 1. 项目总览

### 1.1 三层代码结构

```text
Scripts/Engine/      引擎层（PVZEngine）：实体、碰撞、伤害、网格、计时器。
                     几乎不改，但里面有所有核心 API 的定义。
Scripts/Logic/       逻辑规则层：逻辑实体属性、关卡扩展、grid 扩展。
Scripts/MVZ2/        表现与系统层：模型控制器、资源管理器、UI、Addressables 加载。
Scripts/Vanilla/     原版内容层：所有器械/敌人/Buff/检测器的行为类都写在这里。
                     本手册教你写的代码 99% 落在这一层。
```

### 1.2 内容的两半：代码 + 元数据

一个单位 = **行为类（C#）+ 元数据（XML）+ 模型（prefab）**：

```text
行为类   Scripts/Vanilla/GameContent/Enemies/D_Chapter1/Creeper.cs
         ↑ 挂在实体上，每帧跑逻辑（移动/攻击/爆炸）
元数据   metas/entities.xml   <entity id="creeper" ...>   ↑ 数值与行为接线
模型     models/enemy/Bay/creeper.prefab                     ↑ 外观
三者用同一个名字（creeper）互相咬合。
```

**资产目录速记**（都在 `Assets/GameContent/Assets/mvz2/` 下）：

```text
metas/            所有元数据 XML（entities/models/sounds/stages/maps/areas/spawns/
                  unlocks/buffs/grids/fragments/almanac/talks）
models/           模型 prefab（contraption/enemy/effect/units/... 按类别分目录）
sprites/          实体贴图（PNG + 切片 meta，与 prefab 同名对应）
sounds/           音频文件（wav/ogg，sample path 直接映射子路径）
spritemanifests/  贴图切片登记表（菜单生成）
ResourcePacks/    语言包压缩产物（builtin.bytes）
```

元数据 XML 在**构建时**打进游戏包（Addressables）。改了 XML/模型/贴图后必须重新构建才能在游戏里看到效果；**编辑器 Play 模式无法完整游玩，是项目设计**（内容按 Meta/Model/Sprite/Music 标签走自制 mod 目录，构建版才有完整内容）。

### 1.3 构建流程与排障第一入口

- 构建并运行会自动重建 Addressables（正常耗时约 6 分钟；**只有 1 分多钟 = 跳过了资源重建，你的改动不会生效**）。
- **排障第一入口永远是构建版日志**：`C:\Users\<用户名>\AppData\LocalLow\Cuerzor\MinecraftVSZombies2\Player.log`。
  - `Prefab of model X is missing!` = 模型 prefab 没打进包或 Addressables 地址对不上（见第 6 章）；
  - `Resource not found: mvz2:X` = fragments.xml 等元数据缺条目（无害但建议补）；
  - `Could not find the buff meta for buff definition X!` = C# 注册的 Buff 在 buffs.xml 没有对应条目（见第 5 章）。

### 1.4 改动后的标准操作流

```text
1. 改代码/元数据/prefab
2. 改了 Addressables（main.asset）→ 先重启 Unity（防内存态覆盖磁盘）
3. 完整构建并运行（确认 6 分钟左右）
4. 出问题 → 先看 Player.log，再回来对代码
```

### 1.5 最小概念表（后面章节反复用到）

| 概念 | 是什么 | 关键数值/规则 |
|---|---|---|
| `mvz2:` 前缀 | 本 mod 内容的命名空间。所有 metas XML 里的 id 都写成 `mvz2:名字`，加载时拼成完整 NamespaceID。自己新增的内容**必须**用 `mvz2:` 开头 | metas XML 与 Addressables 地址的通用前缀 |
| tick 与 TPS | 游戏逻辑帧。**30 TPS**（1 秒 = 30 tick）；"90 tick" = 3 秒。FrameTimer/计时器都以 tick 计 | `Ticks.cs`；换算用 `TimerHelper.NewSecondTimer(秒)` |
| Addressables | Unity 的资源打包系统。构建时把模型/贴图/元数据按**地址**（如 `mvz2:contraption/bay/reverse_bomb`）打进游戏包。**模型 prefab 用 Main+Model 标签、贴图用 Main+Sprite** | 配置在 `Assets/AddressableAssetsData/`；条目在 `AssetGroups/main.asset` |
| 模板默认值 | XML 不写的属性继承模板或引擎默认：器械 maxHealth=300、僵尸 200（entities.xml:46/74）；gravity 默认 1；priority/maxCount 等也有默认 | 查模板定义再决定要不要覆写 |
| 阵营 | 0=玩家方（左）、1=僵尸方（右）；爆炸/伤害按阵营区分敌我 | `VanillaFactions`；特殊值 2 = 敌我不分 |

### 1.6 调试控制台（最快的验证手段）

构建版游戏内自带调试控制台（`metas/commands.xml` 定义命令，`DebugManager_Console.cs` 执行）。**命令格式 = 主名 + 子名**（如 `spawn pos`、`energy set`），缺子名会报错：

```text
spawn pos mvz2:creeper                  在场地中心生成一只苦力怕
spawn pos mvz2:creeper 400 0 1 1        指定坐标与阵营（0 友方 / 1 敌方）
starshard add 1                         加 1 个星之碎片（测器械星之碎片能力）
spawnblueprint pos mvz2:reverse_bomb    获得一张器械卡片（测放置/充能）
energy set 1000                         设置红石能量（energy 是红石；星之碎片用 starshard）
help                                    查看全部命令
```

**验证新实体的最快路径 = 控制台 spawn 出来看**，不用等关卡波次。另外行为类里的 `Debug.Log` 输出在编辑器 Console 和构建版 `Player.log` 都能看（第 1.3 节）。

## 2. 实体系统：万物皆实体

### 2.1 实体类型

`Scripts/Engine/Level/Entities/EntityTypes.cs`：

```text
PLANT    器械（玩家种的所有东西，包括 TNT、地雷）
ENEMY    敌人（僵尸系 + 尸解仙之杖这类"实体附属物"）
EFFECT   纯表现效果（爆炸粒子等，不可被攻击）
OBSTACLE / BOSS / CART / PICKUP / PROJECTILE
```

碰撞掩码 `EntityCollisionHelper.cs:16-24`：`MASK_PLANT/ENEMY/OBSTACLE/BOSS` 组成 `MASK_VULNERABLE`（可受伤集合）。**子弹、爆炸能不能打到你，取决于你的类型在不在掩码里**。

### 2.2 实体定义 = XML 里的一个 `<entity>`

**最简敌人：普通僵尸只用了 4 行有效内容**（entities.xml:2119-2131，行为与数值全部来自模板链）：

```xml
<entity template="zombie" id="zombie" name="僵尸" deathMessage="脑子是好的，但不是每个人都有">
    <unlock>
        <condition requiredGroups="mvz2:enemy.zombie" />
    </unlock>
    <behaviours includeSelf="false">
        <behaviour operator="add" id="mvz2:boated_enemy" />              <!-- 水上乘船（可选增强） -->
        <behaviour operator="add" id="mvz2:rickroll_drown_achievement" /> <!-- 彩蛋成就 -->
    </behaviours>
    <properties>
        <int name="mvz2:cost" value="50" />                              <!-- 唯一覆写：阳光费用 -->
        <int name="mvz2:teleporter_cost" value="-25" />
    </properties>
</entity>
```

**它没有专属行为类**——走路、啃食、死亡、动画全部来自模板链（entity→enemy→humanoid→zombie）。再看一个原版的**模板 + 实体**对照（溺尸，模板 entities.xml:298、实体 3569）：

```xml
<!-- 模板：humanoid 的水中版 -->
<drowned type="2" parent="humanoid">
    <properties>
        <id name="mvz2:crySound" value="mvz2:drowned_cry" />
        <id name="mvz2:deathSound" value="mvz2:drowned_death" />
        <int name="mvz2:waterInteraction" value="3" />   <!-- 水中交互模式 -->
    </properties>
</drowned>

<!-- 实体：从模板继承一切，只覆写差异 -->
<entity template="drowned" id="drowned" name="溺尸" deathMessage="沉入海底">
    <behaviours includeSelf="false"/>
    <properties>
        <int name="mvz2:cost" value="50" />
        <int name="mvz2:teleporter_cost" value="-25" />
    </properties>
</entity>
```

三要素：

- **template**：继承哪个模板。模板也是 `<type="2" parent="...">` 形式的中间定义。
- **behaviours**：挂哪些行为类。`operator` 支持 `add` / `remove` / `replace`（replace 是**原位替换**，不改变行为执行顺序——见 2.5）。
- **properties**：数值属性。`<float>/<int>/<bool>/<id>/<vector3>/<idArray>/<color>`，名字统一 `mvz2:开头`。**不写的属性继承模板或引擎默认值**（器械 maxHealth 默认 300、僵尸 200——entities.xml:46/74）。

需要自定义逻辑（自爆、跳跃、特殊攻击）时才写行为类——见第 3/4 章实战与 4.7（本项目新增单位的对照）。

### 2.3 includeSelf：你自己的行为类

XML 解析器默认会把**实体 id 对应的行为类**自动挂上（`EntityMeta.cs:69-73`）。所以：

```xml
<!-- 想让 Creeper 类挂到 creeper 实体：什么都不用写，默认 includeSelf=true 自动挂 -->
<!-- 想完全自己控制行为列表：写 includeSelf="false"，然后手动 add -->
<behaviours includeSelf="false">
    <behaviour operator="add" id="mvz2:creeper" />
</behaviours>
```

**反向坑**：`includeSelf="false"` 会**注销实体自身行为**。如果模板里已经显式 `add` 了自己的行为（比如苦力怕的共享模板），实体再写 `includeSelf="false"` 就是正确做法；但如果忘了 add，行为类就不会挂载，逻辑静默失效。

### 2.4 行为类怎么写

最小骨架（继承 `AIEntityBehaviour`，用注册名自动绑定）：

```csharp
[AutoEntityBehaviourDefinition(VanillaEnemyNames.creeper)]   // 注册名 = "creeper"
public class Creeper : AIEntityBehaviour
{
    public Creeper(string nsp, string name) : base(nsp, name) { }

    public override void Init(Entity entity) { }             // 生成时一次

    protected override void UpdateAI(Entity entity)          // 每帧逻辑（被冰冻时跳过）
    {
    }

    protected override void UpdateLogic(Entity entity) { }   // 每帧逻辑（冰冻也跑）

    public override void PostDeath(Entity entity, DeathInfo info) { }   // 死亡回调
}
```

要点：

- **注册名必须与实体 id 完全一致**（或用 XML `add` 显式挂载）。
- **每帧写 `entity.State` 的 AI 必须先 `if (entity.IsDead) return;`**，否则会覆盖死亡状态、死亡动画不播（踩过的坑，见第 11 章）。
- 需要每帧跑但不受冰冻影响的逻辑放 `UpdateLogic`（如拾取检测、计时器递减）。

### 2.5 行为的执行顺序

行为按 XML 组装顺序执行（`replace` 原位替换）。**先执行的行为设置的状态，后执行的行为当帧就能读到**。例：苦力怕的 `state` 行为（改 `entity.State`）排在动画行为之后——动画行为晚一帧才看到新状态，这是正常的，写逻辑时不要依赖"当帧设当帧读"。

### 2.6 属性与行为字段：两种存储别混用

```csharp
// 实体属性（PropertyMeta）：跨行为共享的"数据表"，存数值/开关
entity.GetProperty<int>(meta);  entity.SetProperty(meta, value);
public static readonly VanillaEntityPropertyMeta<int> META = new("my_field");

// 行为字段（BehaviourField）：同样是实体级存储，常用于行为内部状态
entity.GetBehaviourField<int>(meta);  entity.SetBehaviourField(meta, value);
```

两者的无 ID 重载都是**实体级全局字典**（`EngineEntityExt.cs:21-28`），不同行为类之间读写同一个 meta 名就是读同一个值。meta 名必须全项目唯一（`PropertyMeta` 未注册时会共享 0 号槽，但本项目 `InitPropertyMaps` 扫描链完整，`[Auto...]` 特性类的 meta 会正常注册）。

### 2.7 实体类型速记

```text
EntityTypes.PLANT   → 器械类，会被玩家方子弹"友方碰撞"忽略、被僵尸啃食
EntityTypes.ENEMY   → 敌人类，会被器械索敌、被玩家攻击（可用 not_target 排除，见 10 章）
EntityTypes.EFFECT  → 纯表现，不进任何可受伤掩码，爆炸/子弹/索敌全都打不到
```

## 3. 器械开发实战

### 3.1 起步：照抄最近的同类

写新器械的流程永远是"**找最像的原版器械 → 复制它的 XML 和行为类 → 改差异**"。常用参照：

| 要做什么 | 参照 | 位置 |
|---|---|---|
| 爆炸类（点燃引爆） | TNT | metas/entities.xml:509、`Contraptions/Chapter1/TNT.cs` |
| 踩踏类 | 地雷 TNT | entities.xml:413、`Contraptions/Prologue/MineTNT.cs` |
| 无碰撞小物件 | 打火石（**本项目新增**，结构照原版器械复制，已实测可用） | entities.xml:2084、`Contraptions/D_Chapter1/FlintAndSteel.cs`、`models/contraption/bay/flint_and_steel.prefab` |
| 抛射其他器械 | 弹射器 | `Contraptions/Chapter7/Ejector*.cs`、`GlobalCallbacks/EjectorGlobalCallbacks.cs` |
| 有星之碎片技能的发射器 | 三头发射器 | `Contraptions/Chapter5/Triplenser.cs` |

### 3.1.1 从零新建一个器械的八步

```text
1. 复制 XML：在 entities.xml 复制最像的同类 <entity>，改 id（全小写下划线）与 name
2. 挂行为：模板/ignitable 等接线照抄，需要自定义逻辑的写 <behaviour operator="add" id="mvz2:新id" />
3. 改数值：damage/range/cost/rechargeId 等按需求
4. 写行为类：复制参照的 .cs 到同目录，类名与注册名对齐——
   VanillaContraptionNames 加 const string、VanillaContraptionID 加 static readonly NamespaceID（两处都在 Contraptions/VanillaContraptionID.cs）
5. 模型：prefab 放 models/contraption/bay/，models.xml 加条目，main.asset 登记（GUID+地址，见 6.2）
6. 解锁：unlocks.xml 加 contraption.新id 组（照 TNT），entities.xml 加 <unlock> 引用
7. 编译（dotnet build）→ 重启 Unity → 完整构建
8. 验证：游戏内用控制台 spawnblueprint 新id 拿卡片试放；或通关解锁后测试
```

### 3.2 TNT 的 XML 注解（器械模板范本；已省略 placeSound/deathSound 两条，其余逐字）

```xml
<entity template="contraption" id="tnt" name="TNT" tooltip="触发后炸飞周围敌人">
    <unlock>                                                          <!-- 3.1.1 第 6 步要照抄的解锁块 -->
        <condition requiredGroups="mvz2:contraption.tnt" />
    </unlock>
    <behaviours>
        <behaviour operator="add" id="mvz2:ignitable" />              <!-- 可点燃：30 tick 倒计时爆炸 -->
        <behaviour operator="add" id="mvz2:ignitable/trigger" />      <!-- 触发方式接线 -->
        <behaviour operator="add" id="mvz2:ignitable/evoke" />        <!-- 星之碎片唤醒 = 点燃自己 -->
        <behaviour operator="add" id="mvz2:explode_on_fire_death" />  <!-- 被火烧死时也爆炸 -->
    </behaviours>
    <properties>
        <bool  name="mvz2:canDeactive" value="false" />   <!-- 不可停用 -->
        <bool  name="mvz2:dynamite" value="true" />       <!-- 炸药标记（海怪/红龙吞吃判定用） -->
        <float name="mvz2:damage" value="1800" />         <!-- 爆炸伤害 -->
        <float name="mvz2:range"  value="120" />          <!-- 爆炸半径：120 = 1.5 格（1 格 = 80） -->
        <vector3 name="mvz2:size" x="48" y="48" z="48" /> <!-- 逻辑碰撞盒 -->
        <id name="mvz2:shell" value="mvz2:grass" />       <!-- 外壳材质（受伤音效/减伤） -->
        <bool name="mvz2:triggerActive" value="true" />
        <bool name="mvz2:instantTrigger" value="true" />
        <int  name="mvz2:cost" value="150" />             <!-- 阳光费用 -->
        <id   name="mvz2:rechargeId" value="mvz2:very_long" /> <!-- 充能时长：none/short/long/very_long -->
    </properties>
</entity>
```

要点：`damage` 与 `range` 由 `IgnitableBehaviour` 倒计时结束时通过 `IExplodeContraptionBehaviour.Explode(entity, range, damage)` 接口回调给行为类（`IgnitableBehaviour.cs`，`TryBehaviourExplodeAndRemove` 内含移除自身）。

### 3.3 行为类：接住爆炸回调

```csharp
void IExplodeContraptionBehaviour.Explode(Entity entity, float range, float damage)
{
    // 自己写爆炸。entity.Explode 的 faction 参数决定打谁：
    // entity.GetFaction()（玩家方=0）→ 只伤敌方；特殊阵营值（如 2）→ 敌我不分
    var damageEffects = new DamageEffectList(
        VanillaDamageEffects.MUTE,
        VanillaDamageEffects.DAMAGE_BODY_AFTER_ARMOR_BROKEN,
        VanillaDamageEffects.EXPLOSION
    );
    entity.Explode(entity.Position, range, entity.GetFaction(), damage, damageEffects);
    Explosion.Spawn(entity, entity.GetCenter(), range);   // 爆炸粒子
    entity.PlaySound(VanillaSoundID.explosion);           // 音效
    entity.Level.ShakeScreen(10, 0, 15);                  // 屏幕震动
}
```

（以上为节选，完整实现见 `Contraptions/Chapter1/TNT.cs:44-77`，含炸飞敌人 BlowUpEnemiesToSky。）

**爆炸对 `mvz2:not_target` 实体、`EFFECT` 类型无效**（掩码不含它们）——想造"只能被爆炸摧毁的地面道具"用 `ENEMY` 类型 + `PreTakeDamage` 过滤（见 4.5）。

### 3.4 星之碎片能力（Evoke）

TNT 的模式：`ignitable/evoke` 行为让"星之碎片唤醒 = 点燃自己"，爆炸时用 `entity.IsEvoked()` 区分：

```csharp
// TNT.Explode 内部：普通爆炸无条件发生，星之碎片唤醒时【追加】强化效果（射出 4 发飞行 TNT）
Explode(entity, range, damage);
if (entity.IsEvoked())
{
    EvokedExplode(entity, range, damage);
}
```

注意 TNT 是"追加"而非"替换"——**需要按唤醒与否整体替换爆炸效果时，用 ReverseBomb 的分支写法**（见 3.5：`if (IsEvoked()) StarDetonate(...) else NormalBlast(...)`）。

自定义技能的器械（如三头发射器）则 override `OnEvoke`（`Triplenser.cs:57`）直接执行技能逻辑。星之碎片能量的来源与消耗见第 9 章。

### 3.5 实战例子：弹射器的落地效果系统（原版）

弹射器把器械抛上天后，落地的一切行为由 `ThrownByEjectorBuff` 统一处理（`Buffs/Contraption/Chapter7/ThrownByEjectorBuff.cs`）——这是"空中的实体落地时做一堆事"的标准参照：

**Buff 构造函数**（强制物理与碰撞扩围）：

```csharp
AddModifier(new FloatModifier(EngineEntityProps.GRAVITY, NumberOperator.Set, 1,
    priority: VanillaModifierPriorities.FORCE));   // 强制重力（照抄值）
AddModifier(new FloatModifier(EngineEntityProps.FRICTION, NumberOperator.Set, 0));
AddModifier(new IntModifier(EngineEntityProps.COLLISION_MASK_HOSTILE, IntegerOperator.BitOr,
    EntityCollisionHelper.MASK_VULNERABLE));   // 飞行中会撞伤路径上的单位
```

**落地回调**（PostEntityContactGroundCallback）四步：

```csharp
entity.Position = entity.Level.GetEntityGridPosition(entity.GetColumn(), entity.GetLane());  // 对齐网格
var vel = entity.Velocity; vel.x = 0; vel.z = 0; entity.Velocity = vel;                      // 清动量
entity.DestroyConflictGridEntities();    // 砸毁占格冲突器械（直接 Die）
entity.RemoveBuffs<ThrownByEjectorBuff>();   // 结束弹射状态
```

**飞行中碰撞**（PostEntityCollisionCallback）：撞到敌对单位按体积×密度算撞击伤害（`CalculateSmashDamage`）。落地还会按**外壳类型**分派特殊效果（闪电落雷/下界岩留火/冰爆冰锥——`EjectorGlobalCallbacks.cs:50-88`）。

**本项目应用**：颠倒炸弹的进化体落地砸毁就是复用这套思想（`ContraptionInvertedBuff.cs:133` 用 `DestroyConflictGridEntitiesOnLand()` 挂落地自动砸毁）。

### 3.5.1 本项目新增对照：颠倒炸弹（ReverseBomb.cs）

TNT 骨架 + `IsEvoked` 分支替换爆炸效果（见 3.4 的"替换"写法）：普通引爆 = 600 对敌爆炸 + 范围内施加颠倒/高压；星之碎片引爆（evoke 点燃自己）= 无伤害、全场器械颠倒/清敌方苦力怕高压/全场苦力怕绝缘。施加效果的检测器写法见 3.5 的 SphereDetector 模板。**已实测可玩**。

### 3.6 实战例子：地雷（踩踏触发）

`MineTNT.cs`：不用检测器，用**碰撞回调**（以下为节选，完整实现含准备计时器与音效，见 `Contraptions/Prologue/MineTNT.cs:134-158`）：

```csharp
public override void PostCollision(EntityCollision collision, int state)
{   // 节选：self/otherCollider/riseTimer 来自上文（self = collision.Entity）
    if (state == EntityCollisionHelper.STATE_EXIT) return;
    var other = collision.Other;
    if (!other.IsVulnerableEntity() || !self.IsHostile(other)) return;
    if (!otherCollider.IsForMain()) return;           // 只认主碰撞盒
    if (!riseTimer.Expired) return;                   // 准备完成才炸
    // 到时（riseTimer.Expired）才炸
    self.Explode(self.Position, self.GetRange(), self.GetFaction(), self.GetDamage(), effects);
}
```

碰撞盒大小 = XML `mvz2:size`（地雷 48×24×48）——"触发范围"就是碰撞盒。

### 3.7 实战例子：把别的器械抛上天（弹射器）

弹射器把器械抛上天后，**被抛器械挂 `ThrownByEjectorBuff`**（`Buffs/Contraption/Chapter7/ThrownByEjectorBuff.cs`），该 Buff：

- 强制 `GRAVITY=1`、`FRICTION=0`、碰撞掩码扩到 `MASK_VULNERABLE`（飞行中会撞伤路径上的单位）；
- `PostEntityContactGroundCallback`（落地）：**对齐网格** `GetEntityGridPosition(GetColumn(), GetLane())` → 清动量 → **`DestroyConflictGridEntities()`**（把落点格上的冲突器械直接秒杀）→ 移除标记；
- `PostEntityCollisionCallback`（飞行中）：撞到敌对单位按体积×密度算撞击伤害。

**这套"空中物体落地"的机制可以整体复用**（颠倒炸弹的进化体落地砸毁就是照它写的）。

### 3.8 手持道具（铲子 / 点燃 / 星之碎片怎么实现的）

玩家的"手里拿的东西"是一套手持道具系统：**鼠标上挂一个道具定义 + 行为，点击目标触发回调**（`HeldItems/Behaviours/Main/`）。

## 4. 敌人开发实战

### 4.1 敌人模板链

```xml
<zombie type="2" parent="humanoid" />                    <!-- zombie 模板：humanoid + 僵尸特有 -->
<humanoid type="2" parent="enemy">                       <!-- humanoid：替换通用动画为人形动画 -->
    <behaviour operator="replace" source="mvz2:enemy_common_animation" id="mvz2:humanoid_animation" />
    <properties>
        <id name="mvz2:shape" value="mvz2:humanoid" />   <!-- 人形骨骼（决定护甲挂点等） -->
    </properties>
</humanoid>
```

敌人五件套行为（enemy 模板自带）：`enemy_common`（出界/对齐/动画参数）、`enemy_state`（状态机）、`enemy_walk`（走路速度）、`enemy_death_disappear`（死亡 30 tick 后烟雾消失）、`enemy_melee`（啃食）。**特殊敌人只 remove/replace 需要改的**。

### 4.1.1 从零新建一个敌人的八步

```text
1. 复制 XML：在 entities.xml 复制最像的敌人（普僵/铁盔/原版同类），改 id 与 name
2. 行为接线：默认继承 enemy 全套；要自定义 AI 就 replace enemy_state 或 add 新行为
3. 改数值：maxHealth/speed/damage/size/shell 等（不写的继承模板默认，见 1.5）
4. 写行为类：复制参照 .cs，注册名与实体 id 一致（或 replace 的 id 加 /后缀）
5. 模型：prefab 放 models/enemy/<章节>/，models.xml 加条目，main.asset 登记（6.2 三处对齐）
6. 图鉴（可选）：almanac.xml 加条目 + fragments.xml 加碎片颜色（9 章）
7. 出场：spawns.xml 加 entry（进波次池）或写关卡/脚本生成（8.3）
8. 编译 → 构建 → 控制台 spawn 验证 → 再测死亡/移动/索敌
```

### 4.2 移动速度的铁律

`VanillaEnemyExt.cs:35-49`：实际移速 = `mvz2:speed` × `0.4`（`WALK_SPEED_FACTOR`）。要 2 倍普僵就写 `speed=2`。

改速度**不要每帧写**（事件驱动：在速度该变的事件点调 `SetSpeed`，并把 `RandomEnemySpeedBuff` 固定成 1 倍防随机数干扰——`PoleVaultingZombie.SetSpeed` 是标准写法）。

### 4.3 最简敌人：纯 XML 的普通僵尸（零行为类）

普通僵尸**没有任何专属行为类**——走路、啃食、死亡、动画全部由模板链提供（见 2.2）。**改数值就能做出新敌人**：铁盔僵尸 = 普僵 + `starting_armor` 初始护甲（entities.xml:2154 附近），皮帽溺尸 = 溺尸 + 护甲。

**要加自定义逻辑**（自爆/跳跃/特殊攻击）才写行为类——参照 4.4 与 4.7。

### 4.4 原版跳跃状态机：骷髅马（SkeletonHorse.cs，Chapter3/）

骷髅马是原版"跳跃 + 落地结算"的完整参照。**三状态**：

```text
JUMP_STATE_JUMP（跳跃中）→ 落地 → JUMP_STATE_LAND（15 tick 停顿，SetLandTimer）→ GALLOP（奔跑）
```

**跳跃触发**（UpdateStateGallop）：`detector.DetectExists(entity)` → 抛物线起跳（`vel.x = facing × 5, vel.y = 12`——照抄的标准跳跃数值）。

**落地回调**（PostContactGround）：

```csharp
if (entity.State == STATE_JUMP)
{
    stateTimer?.Reset();                                  // 15 tick 停顿开始
    SetJumpState(entity, JUMP_STATE_LAND);
    entity.PlaySound(VanillaSoundID.horseGallop);
}
```

**撞高器械清速度**（UpdateLogic）：

```csharp
if (blocksJumpDetector.DetectExists(entity) && GetJumpState(entity) == JUMP_STATE_JUMP)
{
    var vel = entity.Velocity; vel.x = 0; vel.y = 0; entity.Velocity = vel;
    entity.Stun(30);                                      // 撞晕
    entity.PlaySound(VanillaSoundID.bonk);
}
```

`blocksJumpDetector`（`Detections/SkeletonHorseBlocksJumpDetector.cs`）检测"与自身重叠且带 `BlocksJump` 属性的器械"——**只有足够高的器械才能挡住跳跃**。

### 4.5 实战例子：实体附属物（尸解仙之杖）

僵尸身上"掉出来的部件"用 `specialEnemy` 模板（`entities.xml:249`）：

```xml
<entity template="specialEnemy" id="shikaisen_staff" name="尸解仙之杖" deathMessage="？">
```

`specialEnemy` 移除了 `enemy_state/enemy_melee/enemy_walk`——变成无 AI 静态实体。关键属性：

```text
harmless=true          无攻击性
notActiveEnemy=true    不算活动敌人（不阻止关卡清场）
noReward=true          无掉落
loyal=true
immune_slowing=true    免疫减速
fallResistance=10000   不可被吹飞
```

行为类里用 `PreTakeDamage` 改伤害（尸解仙杖：火伤 = 最大血量×10 秒杀）。**注意：ENEMY 类型默认会被器械索敌**——要免疫索敌加 `mvz2:not_target=true`（引擎属性，`Detector` 基类统一排除；需要被检测的检测器加 `canDetectNoTarget=true` 放行）。

**关键属性说明**：上面列出的 harmless/notActiveEnemy/noReward 等是 **shikaisen_staff 实体逐条自己写的**（entities.xml:3269 起），不是 specialEnemy 模板自带的——specialEnemy 模板只 remove 三个行为（entities.xml:249-255），其余属性都要逐条抄。

### 4.6 死亡与移除的语义差异

- `entity.Die()` 走完整死亡链：`PreDeath → IsDead → 行为 PostDeath → POST_ENTITY_DEATH 广播`。死亡音效、掉落都挂在这条链上；
- `entity.Remove()` 直接从场上消失，**不走任何死亡逻辑**——自爆类单位用它（苦力怕自爆）、器械的普通死亡也用它；
- **死亡后的残留差异（器械与敌人不同）**：
  - **敌人**：`enemy_death_disappear` 行为让尸体停留 **30 tick** 后烟雾消失（`EnemyDeathDisappearBehaviour.cs`，敌人模板自带）；
  - **器械**：死亡**立即 Remove**（`ContraptionCommonBehaviour.cs:37-47` 的 PostDeath 两个分支都直接移除）；
- 铲除走 `Die(PICKAXE)` 伤害效果——**会触发 POST_ENTITY_DEATH**（颠倒结算等死亡钩子都会跑），但不触发 `POST_CONTRAPTION_DESTROY`。

### 4.7 本项目新增单位的对照（苦力怕 / 真化 / 多杆撑杆）

以下单位是本 mod 新增（`Enemies/D_Chapter1/`、`Chapter1/PoleVaultingZombie.cs`），机制细节见代码内注释——**它们复用了上述原版模式**：

- **苦力怕**：自爆 = 蓄力（IDLE + casting + charge ±1）+ 蹬地帧爆炸 + `Remove()`（不走死亡链）；**死亡早退坑**见第 11 章 #1；
- **真化苦力怕**：继承苦力怕类、override 爆炸方法替换为全场效果；真名解放 = Buff 标记 + 模型属性换肤；
- **多杆撑杆跳**：骷髅马跳跃结构 + 预备 12 帧 + 多杆计数与拾取（杆实体 = specialEnemy 模板同款写法）；
- 已知问题与调试日志（[PoleDebug]/[DeathAnim]）见第 11 章。

## 5. Buff（状态效果）开发实战

### 5.1 组词链：一个 Buff 的三处名字必须逐字一致

```text
C# 常量   VanillaBuffNames.Enemy.insulated = "insulated"
特性      [AutoBuffDefinition(VanillaBuffNames.Enemy.insulated)]   → 注册为 mvz2:insulated
XML       buffs.xml:  <buff id="insulated" polarity="negative" level="2000" target="enemy" />
```

- snake_case 全小写下划线（`creeper_charging`、`tnt_ignited`）；**大小写不一致会导致 meta 查不到**（日志警告 `Could not find the buff meta`）；
- **状态类 Buff 用过去分词**（被怎么了的）：`inverted`、`imitated`、`psychic_shackled`；
- 分类分区：器械类挂 `Contraption`、敌人类挂 `Enemy`（常量与 NamespaceID 定义都在 `Buffs/VanillaBuffID.cs`）；
- **UI 显示名不来自 buffs.xml**，来自本地化翻译目录（第 10 章）。

### 5.2 时长与刷新的标准模式

```csharp
public class InsulatedBuff : BuffDefinition   // 本项目新增；原版同类先例见 Buffs/Enemies/Chapter4/SlowBuff.cs
{
    public override void OnCreate(Buff buff)
        => buff.SetProperty(PROP_TIMER, TimerHelper.NewSecondTimer(DURATION_SECONDS));
    public override void PostUpdate(Buff buff)
    {
        if (GetTimer(buff).RunToExpiredOrNull())
            buff.Remove();          // 到期自动消失
    }
    public static void Apply(Entity entity, float durationSeconds = DURATION_SECONDS)
    {
        var buff = entity.GetFirstBuff<InsulatedBuff>() ?? entity.AddBuff<InsulatedBuff>();
        buff.SetProperty(PROP_TIMER, TimerHelper.NewSecondTimer(durationSeconds));  // 重复施加=刷新
    }
}
```

- `TimerHelper.NewSecondTimer(30)` = 30 秒（内部按 TPS 换算 tick，别手写 900）；
- **重复施加 = 刷新到满值**（不要叠加多个实例）；
- 调用方（行为类）只调 `XxxBuff.Apply(entity, 秒数)`。

### 5.3 原版范例：诅咒蜡烛（死亡触发的 Buff）

`CursedCandleBuff`（`Buffs/Entity/Chapter6/CursedCandleBuff.cs`）是"Buff 监听宿主死亡并做出反应"的原版参照：

```csharp
[AutoBuffDefinition(VanillaBuffNames.Entity.cursedCandle)]
public class CursedCandleBuff : BuffDefinition
{
    public CursedCandleBuff(string nsp, string name) : base(nsp, name)
    {
        AddModelInsertion(LogicModelHelper.ANCHOR_CENTER,          // 挂一个蜡烛模型
            VanillaModelKeys.candleCursed, VanillaModelID.candleCursed);
        AddModifier(new BooleanModifier(LogicEntityProps.REMOVE_ON_DEATH, true));
        AddTrigger(LevelCallbacks.POST_ENTITY_DEATH,                // 监听宿主死亡（LATE 优先级）
            PostEntityDeathCallback, VanillaCallbackPriorities.LATE);
    }
    public override void PostUpdate(Buff buff)                      // 常规伤害：每 1 秒自伤
    {
        if (timer.RunToExpiredAndNotNull())
            entity.TakeDamageSourced(GetFireDamage(buff), fireEffects, ...);
        timer.Reset();
    }
    private void PostEntityDeathCallback(EntityDeathParams param, ...)
    {
        // 宿主死亡：按携带参数爆炸（ExplodeAgainstFriendly）+ RemoveBuffs(this)
    }
}
```

要点：**伤害与爆炸的参数都走 buff.SetProperty 存储**（`PROP_FIRE_DAMAGE/PROP_EXPLOSION_DAMAGE`），可在施加时定制——这是"可配置 Buff"的原版范式。

### 5.4 原版范例：TNTIgnitedBuff（纯标记型 Buff）

`TNTIgnitedBuff`（`Buffs/Contraption/Chapter1/TNTIgnitedBuff.cs`）是**最简标记型 Buff**：核心是无敌 modifier 与闪烁（PostUpdate 改 COLOR_OFFSET），**自身不含业务逻辑**——点燃状态由 `IgnitableBehaviour` 的属性管理，Buff 只提供外观与无敌：

```csharp

// 闪烁在 PostUpdate 改 COLOR_OFFSET
```

## 6. 模型、贴图、Addressables：紫黑格与失踪模型的救赎

### 6.1 实体模型 prefab 的标准结构

独立实体模型 prefab **必须**有模型宿主四件套（最省事的做法：**直接嵌套 `Prefabs/Models/EntityModel.prefab`**，flint_and_steel.prefab 就是这么做的）：

```text
SortingGroup                    渲染排序容器
模型宿主（9abc2d1d…脚本）        字段：sortingGroup/modelCollider/group/bone
ModelGroupEntity（05186337…）   元素收集：renderers/animators/modelAnchors 数组
```

- `renderers` 数组**引用** prefab 里的 RendererElement 组件；
- **`modelCollider` 为空 = 实体收不到爆炸/碰撞命中**（哪怕 XML size 正常）；
- 无动画的实体 `animators` 数组留空即可。

### 6.2 models.xml 与 Addressables：三处名字必须逐字对齐

```text
models.xml   <model name="reverse_bomb" path="mvz2:contraption/bay/reverse_bomb" ...>
                     ↑ 实体默认 modelId = mvz2:entity.reverse_bomb → 按 name 匹配条目
Addressables main.asset 条目：  m_GUID = prefab 的 GUID
                                m_Address = mvz2:contraption/bay/reverse_bomb   ← 必须与 path 逐字一致
                                m_SerializedLabels: Main + Model（模型 prefab 用 Model，贴图用 Sprite）
```

**事故模式**：条目 GUID 填错（拖成了贴图）→ 构建时 Addressables 把**贴图**绑到模型地址 → 加载返回非 GameObject → `Prefab of model X is missing!` → 器械上渲染紫黑方格。**修好后必须重启 Unity 再完整构建**（Addressables 有内存态，改了磁盘不重启会被覆盖）。

### 6.3 贴图与 SpriteManifest

- 器械/敌人贴图放 `sprites/entity/<分类>/`，`.meta` 里切片（spriteMode 1=单图，2=Multiple 切片）；
- `spritemanifests/manifest.asset` 是**切片登记表**（SpriteRendererResolver 反查 key 用）——由编辑器菜单生成（`Editor/Menus/SpriteMenu`）；
- **没登记 manifest 的贴图也能显示**（resolver 对未知 sprite 原样返回——ts_creeper/pole 先例），但资源包覆盖能力会缺失；改动贴图后建议重新生成 manifest；
- **紫黑方格** = 材质/贴图丢失（编辑器表现）——按 6.2 查三处名字对齐。

### 6.4 诊断流程（模型类问题）

**资源丢失的表现先分清**：sprite 引用丢失（Missing Sprite）= SpriteRenderer **空白不渲染**；材质/shader 丢失或不兼容渲染管线 = **紫红色**（Unity 的错误着色器）——你看到的"紫黑方格"属于后者。

```text
1. Player.log 搜 "is missing"     → 有 = Addressables/登记问题（6.2）
2. main.asset 条目 GUID ↔ prefab.meta GUID 对比
3. main.asset 地址 ↔ models.xml path 逐字对比（含大小写与斜杠段数）
4. prefab 结构对照 EntityModel.prefab 四件套 + modelCollider
5. 紫黑格/透明 → 查 m_MaskInteraction（=1 无遮罩静默不可见；=2 有 SpriteMask 覆盖时被裁）与材质引用
```


### 7.1 贴图切片：一张 PNG 拆成多个部件

1. PNG 放进 `sprites/entity/<分类>/`（与同类别贴图同目录）；
2. 选中 PNG → Inspector → Texture Type = Sprite (2D and UI)、Sprite Mode = Multiple、
   Pixels Per Unit = 100（项目惯例）→ **改完先点检查器面板右下"应用"**（没改动时按钮
   不显示，新人常到处找）；
3. 点 Inspector 里的 **"精灵编辑器"按钮**（Sprite Editor）→ 左上 **"切片"▾** 弹层
   （"按单元大小切片"在弹层里设置）→ **点弹层内的"切片"按钮才真正生成切片框** →
   **窗口右上再点一次"应用"**（精灵编辑器的"应用"与 Inspector 的是两个独立按钮，
   只点后者切片全丢）；
4. **切片名默认即可**（自动 `<文件名>_0/1/2`，引用走 internalID；要批量改名可用菜单
   MVZ2/Assets/Sprites/Rename Sprites）。

先例：`sprites/entity/enemy/creeper.png`（5 片：身体/腿），`reverse_bomb.png`（单图 spriteMode:1）。
**单图（spriteMode 1）的 fileID 恒为 21300000**；切片模式每片有自己的 internalID。

**红线**：Multiple 贴图的**整张 PNG**拖进 SpriteRenderer 的 Sprite 槽时，Unity 会弹
"Set Texture to Single"对话框——点 Yes 会改写导入设置并**毁掉全部切片引用**（引用切片
一律点 PNG 左侧展开箭头后拖单片）。

### 7.2 模型 prefab：嵌套 EntityModel 基座

**不要从零搭**——复制一个结构最像的原版模型 prefab 改（无碰撞小物件抄 `models/contraption/bay/flint_and_steel.prefab`，
人形抄 `models/enemy/prologue/zombie.prefab`）。标准结构（所有实体模型都长这样）：

```text
根节点
 ├─ SortingGroup                        渲染排序容器（挂模型根）
 ├─ EntityModel（模型宿主，9abc2d1d…）   字段：sortingGroup/modelCollider/group/bone
 ├─ ModelGroupEntity（05186337…）        元素收集：renderers/animators/modelAnchors/transforms/particles
 └─ Sprite 子节点
     ├─ SpriteRenderer（m_Sprite 引用切片；m_MaskInteraction 照抄来源 prefab）
     ├─ SpriteRendererResolver（542a3a60…，必须有——资源包覆盖与换图都靠它）
     ├─ RendererElement（47ce2b2a…）
     └─ BoxCollider2D（modelCollider 引用它——没有它爆炸/碰撞收不到命中）
```

**编辑入口与保存语义**：改 prefab 内容要先**双击 prefab 进"预制件模式"**——
场景视图顶部变蓝条、左上是"◀ + prefab 名"、右上多 **"自动保存"勾选**（Auto Save，
2022.3 默认勾选）。勾选开 = 改动即时落盘、退出**没有保存对话框**；被手滑取消时退出才弹
提示——**预制件模式内不存在"应用/还原"下拉**（那是场景实例的控件）。改完点场景视图
左上 ◀ 退出。

**复制出来的是什么**：右键"复制"后看图标右下角的 **＋ 徽章**——有 = 变体
（zombie 系复制出来还是同基座变体），无 = 独立副本；**变体的 EntityModel 四件套全在
基座上、Inspector 蓝色继承值——不要动**。

**复制后要改的（只有两处）**：

```text
- Sprite 子节点的 m_Sprite：换成自己的贴图切片
  （Project 窗口点 PNG 左侧展开箭头 → 单个切片拖到 SpriteRenderer 的 Sprite 槽；
    手写 YAML 的行格式：m_Sprite: {fileID: <切片 internalID>, guid: <PNG.meta 的 guid>, type: 3}）
- 节点名：改成有意义的名字
```

**不要动的**：EntityModel 四件套字段、renderers/animators 数组的内部 fileID 引用——复制时
原样保留、继承自基座且已经是对的（Inspector 里蓝色字体 = 可 override 的继承值）。

**新增子节点**（加部件/加骨骼）：新节点要有 SpriteRenderer + **RendererElement** 组件，
并且必须把 RendererElement **登记进根上 ModelGroupEntity 的 renderers 数组**（Size+1 拖入）——
漏登记 = 该部件静默不渲染（无报错）。

制作流程：

```text
1. Project 里复制最像的 prefab（右键 →"复制"）→ 改名
2. 双击进"预制件模式"→ 按上面清单改
3. 退出预制件模式 → models.xml 加条目（见 6.2）→ main.asset 登记（GUID+地址+标签 Main+Model）
```

**嵌套原理**（改 YAML 前必读）：敌人类是三层嵌套——
`EntityModel.prefab（基建）← zombie_base.prefab（人形基座）← 你的实体.prefab（变体）`；
器械类多为**两层**（EntityModel.prefab ← 器械.prefab，如 flint_and_steel）。
变体（Variant）可以：改字段引用、加子对象（m_AddedGameObjects）、加组件（m_AddedComponents）、删子对象。
**不能**：重排基座已有骨骼、改基座未 override 的隐藏值。
**手写 YAML 前必须关闭 Unity**（内存态会在焦点切换时覆盖磁盘文件——踩过的坑）。

### 7.3 动画参数怎么从代码到达 Animator

运行时 Animator 组件是被**手动驱动**的（`ModelGroup.cs:24-43` 的 UpdateAnimators：先 `enabled=false` 再逐帧 `animator.Update(dt)`）——这是官方 API `Animator.Update` 支持的手动求值方式，但官方文档警告它"可能与物理引擎等由游戏循环正常驱动的系统配合不佳"——本项目靠逻辑与渲染共用同一 tick 驱动来规避。参数设置链：代码 → `Model.SetAnimatorBool/Int/Float` → 遍历模型上所有 AnimatorElement → `Animator.SetBool/...`。
**每帧写参数**官方无性能警告（字符串重载才有——用 int 常量重载是社区最佳实践）；本项目的动画行为每帧重写全部参数属于 State 驱动映射的惯例。

所以：

- 动画状态切换 = 代码设参数（如 `WalkState`、`Dead`）→ Animator 状态机的 transition 条件响应参数变化；
- **参数名与类型必须与 controller 完全一致**（多写或少写都静默失效）。

### 7.4 新动画四步（以撑杆跳 idle/jump 为例，先例 `pole_vaulting_zombie/base/*.anim`）

**前提（新手必卡的第一步）**：动画窗口只认**场景层级或预制件模式里打开的节点**——
在 Project 窗口里选中 prefab 资产时动画窗口是空白的。所以：

```text
0. 双击模型 prefab 进预制件模式（Scene 视图顶部变蓝条、左上"◀ + prefab 名"），
   选中要动的骨骼节点；"自动保存"默认勾选 = 改动即时落盘、退出无对话框
```

```text
1. 节点上挂 Animator（动画器）组件（复制的人形基座已自带继承的 Animator）：
   动画窗口中央大按钮 **"创建"** → 弹"创建新动画"保存对话框——
   **默认文件名 = 节点名**（如 Body.anim）、**默认目录 = 上次保存目录（不是 prefab 目录）**——
   手动改成 Assets/Animation/Entities/Enemies/<单位>/base/；
   保存后 Unity 在**与 .anim 同目录**生成同名动画控制器（.controller）并赋给 Animator
   （先例：pole_vaulting_zombie.controller 与 base/ 同层）
   ——**红线**：若 Animator 槽里已有共享 controller（如 humanoid.controller），
   "创建"不再弹窗，改为左上 clip 下拉 →"创建新剪辑"——新 clip 会**直接加进
   那个共享 controller 资产**，全体共用它的单位都被波及；想隔离先复制一份 controller
   再拖进 Animator 槽
2. K 帧：**"添加属性"** → 弹菜单按 **子物体路径 → 组件 → 属性** 展开（Transform 下
   位置/旋转/缩放每根轴是独立行）——**骨骼摆动只加"旋转.z"一行**
   （X/Y 别加，加 = 写死姿态；先例 pole_vaulting idle 只绑 localEulerAnglesRaw.z）
   → 播放头移到时间点 → 调整骨骼角度 → 每行右侧悬浮出现的 **◆（添加关键帧）**
   精确落帧（工具栏红 ● 是全局录制，任何改动都自动进 key，容易误 K 一堆）
3. **"循环时间"勾选框在 .anim 资产的检查器面板**（Project 选中 clip → Animation 段
   勾选"循环时间"），不在动画窗口底部（那里只有"采样率"）；不勾 = 播一遍停住
   （跳跃/死亡类）
```

- **器械/Sprite 型模型没有骨骼**（无 Root/Center/Main/Body 层级）——直接选中
  Sprite/Body 节点 K Transform 曲线即可；
- 曲线绑定 path 是**骨骼层级路径**（如 `Root/Center/Main/Body/InnerArm`）——path 写错 =
  该曲线静默无效；
- **预览 ≠ 运行**：Animation 窗口/Inspector 的预览无视代码参数；**空场景 Play 动画不动**
  （没有逻辑层驱动）——**验证必须进真实关卡**（实体系统刷出模型后由代码设参数驱动）。

### 7.5 状态机接线：参数驱动的状态切换

以原版骷髅马（`Chapter3/SkeletonHorse.cs` + `skeleton_horse.controller`）三状态为例——**Animator 参数是 AnimationState（Int）**：实体侧常量在 `VanillaEnemyStates.cs`（JUMP/GALLOP/LAND），动画侧由 `SkeletonHorse_AnimationBehaviour.cs:15-33` 映射写入（两边数值一致）：

```text
AnimationState 数值：JUMP = PRIVATE_NUMBER+0、GALLOP = +1、LAND = +2
状态流转：GALLOP（奔跑，detector 发现目标）→ JUMP（起跳：抛物线速度）→ 落地 → LAND（15 tick 停顿）→ GALLOP
```

**打开动画器窗口**：双击 Project 里的 .controller 文件；或在"预制件模式"选中挂
动画器组件的节点（窗口自动跟随）。确认左上显示的是你的 controller。

**在动画器（Animator）窗口里要做的四件事**（前三件是新人必卡的三连，第四件是静默坑）：

```text
1. 建参数：左上"参数"面板 ＋ → 浮点/整数/布尔/触发四种选 → 行内出现默认名
   "New Int"，点名字段改名回车；类型建错只能删了重建
2. 生成状态：把 .anim 从 Project 拖进动画器窗口 → 自动生成状态节点
   （状态名 = clip 文件名；第一个拖入的自动橙色默认）
3. 设默认状态：右键状态 →"设为层默认状态"（第二个及以后拖入的状态
   不会自动成为默认）
4. 登记 AnimatorElement：给挂 Animator 的节点加 AnimatorElement 组件
   （同一节点，RequireComponent(Animator) 会自动带出 Animator 引用），
   并把该 AnimatorElement 拖进根上 ModelGroupEntity 的 animators 数组（Size+1）
   ——复制的人形基座已自带时无需重复加；漏了 = 编辑器预览动、游戏里静默不播
```

- **过渡线（transition）**：右键源状态 →"创建过渡"→ 点箭头 → 检查器面板：**先取消
  "退出时间"勾选**（不取消则条件只在过退出时间后才评估——"加了条件却一直不切"的
  新人经典卡点），再在底部"条件"列表 ＋ 加条件（读参数）；
- **无过渡指向的状态**：参数永远满足不了 = 实体**永远停在默认状态**，静默无报错；
- 代码侧：`entity.State` 与行为字段记录当前状态，动画行为每帧映射成 AnimationState 写入
  （`SetAnimationInt`）；
- 人形单位的通用参数：`Dead`（bool）、`WalkState`、`ArmState`、`SpecialState`
  （`HumanoidAnimationBehaviour.cs:53-56` 每帧写入）。

### 7.6 代码驱动换图/显隐（不用 K 帧的两种方式）

**逐帧换图（切片动画）**：Sprite 节点挂 `AnimationSpriteSetter`（`Animation/AnimationSpriteSetter.cs`）。
**K 帧时先选中挂了该组件的节点**（Animation 窗口的 Add Property 只列当前选中对象的组件）。
Inspector 填 `sprites` 数组：

```text
1. 组件的 sprites → Size 改成帧数（如 3）
2. Project 窗口点 PNG 左侧展开箭头 → 单个切片逐个拖进 Element 0..N
```

驱动方式二选一：

- **动画驱动**：动画窗口左下切 **"曲线"模式**（英文界面 Curves）→ "添加属性" → 组件的
  `index` 字段 K 整型阶梯曲线——**关键帧右键设 Both Tangents = Constant**（"Dope Sheet"
  模式没有该右键项），否则中间帧会插值乱跳（原版先例 `locked_chest_open.anim`，绑的就是
  该组件的 index）；
- **代码驱动**：换 `ModelPropertySpriteSetterInt` 组件（propertyName 填同名模型属性），
  `entity.SetModelProperty("属性名", int)` 按数值取图。

**显隐开关**：节点挂 `ModelPropertyGameObjectActivatorBoolean`（GUID 6a287da2…），
字段 `propertyName`（模型 bool 属性名）+ `whenFalse`（属性等于此值时隐藏）；
代码 `entity.SetModelProperty("PoleVisible", true)` 控制显隐（撑杆跳手杆先例，
pole_vaulting_zombie.prefab 三个杆节点分别绑 PoleVisible/Pole1Visible/Pole2Visible）。

### 7.7 渲染层级惯例

官方 2D 排序优先级：**Sorting Layer → Order in Layer →（前两者相同时）与相机的距离**——正交 2D 下这个距离默认就是 Z 轴，所以 Z 并非完全不参与，只是被 order 抢占了优先级。本项目用显式 order 分层：

- 模型根挂 SortingGroup（order 0 起步）；组内 SpriteRenderer 用 sortingOrder 手工分层；
- 人形骨架惯例：order 0/10/20/30/40/50/60（humanoid.prefab），特殊层 1000；
- 本项目实例：creeper 身体 20、腿 10；
- `m_MaskInteraction` **新旧资产混用**：护甲与人形（creeper/humanoid）普遍 2（VisibleOutsideMask），zombie 系/flint_and_steel 未设置（默认 0）——**复制谁就保持谁**；
- 多层子排序用 ModelGroupEntity 的 `subSortingGroups`（zombie_base 注册 4 组先例）。

### 7.8 本章坑速查

```text
1. 模型组的 renderers/animators 数组塞错组件类型（把 Animator 组件填进 List<AnimatorElement>）→ 参数/渲染静默失效
2. EntityModel 的 modelCollider 没引用 collider → 收不到爆炸/碰撞命中
3. 手写 YAML 前不关 Unity → 内存态覆盖磁盘
4. m_MaskInteraction=1 且无遮罩 → 静默不可见（不报错）；=2 只在遮罩外渲染
5. 改贴图/切片后不重跑 Update Sprite Manifest → 运行时找不到切片
6. 动画曲线 path 写错 → 静默无效（不报错）
7. Animator 参数名/类型与 controller 不一致 → 静默失效
```

## 9. 关卡、波次、地图、解锁、星之碎片

### 9.1 关卡（stages.xml）

一个完整关卡的骨架（万圣夜第 1 关摘录，stages.xml:34-48；对话本体在 `metas/talks/halloween.xml`）：

```xml
<stage id="halloween_1" name="万圣夜" dayNumber="1">
    <unlock><condition required="mvz2:level.prologue" /></unlock>   <!-- 通关前置 -->
    <talks>                                                          <!-- 对话必须包在 <talks> 里 -->
        <talk type="start" value="mvz2:halloween_1" />               <!-- 开场/结尾/选关对话 -->
        <talk type="end" value="mvz2:halloween_1_over" />
        <talk type="map" value="mvz2:halloween_1_map" />
    </talks>
    <clear pickupModel="mvz2:entity.blueprint_pickup"              <!-- 过关奖励：掉蓝图拾取物 -->
           pickupContentID="mvz2:small_dispenser" />
    <spawns flags="1" pointsPower="0.833">                          <!-- 1 面旗、出怪强度 -->
        <spawn id="mvz2:zombie" />                                  <!-- 候选敌人：引用 spawns.xml 的 entry -->
        <spawn id="mvz2:leather_capped_zombie" />
    </spawns>
    <time firstWave="60" />                                         <!-- 首波时间（秒），缺省 540 帧 -->
</stage>
```

### 9.2 波次的数学（没有逐波 XML）

- **总波数 = 旗数 × wavesPerFlag**（默认 10，`StageDefinition.cs:15`）；**大波 = 波数 % wavesPerFlag == 0**；**最后一波 = 总波数**（`EngineStageProps.cs:39-51`）；
- XML 只定义**旗帜数（flags）+ 出怪强度（pointsPower）+ 候选敌人池**，波次由参数化生成（`StageMeta.cs:129-156`）；
- **要精确指定某波出什么**：用 `<fixedSpawn>`（`StageMeta.cs:147-155`）或写关卡 Definition 类（例：`Stages/Definitions/Adventure/Castle11.cs`）；
- 波次状态机：NOT_STARTED→STARTED→HUGE_WAVE_APPROACHING（大波前 6 秒拉警报）→FINAL_WAVE（`WaveStageBehaviour.cs:72-91`）；
- 场上敌人少/血量低时会**提前进下一波**（`WaveStageBehaviour.cs:111-141`）。

### 9.3 生成资格（spawns.xml）

**敌人必须有 spawn 条目才能进波次**（否则只能脚本生成）：

```xml
<entry id="zombie">
    <entity id="mvz2:zombie" />
    <spawn level="1" />                                    <!-- 从第 1 关起出现 -->
    <terrain water="true" air="true" />                    <!-- 可出环境 -->
    <weight base="4000" decreaseStart="5" decreaseEnd="25" decreasePerFlag="180" />
</entry>
```

`weight` 是按旗数衰减的抽怪权重（解析见 `Metas/Spawns/SpawnMeta.cs:128`）；旗帜僵尸 `weight base="0"` = 永不随机出现（只在 fixedSpawn/旗帜逻辑出）。

### 9.4 地图与区域

- **区域**（areas.xml）：`<area id="day" model="mvz2:day" music="mvz2:day" tags="mvz2:day mvz2:no_water">`；**网格**：`<grids width="80" height="80" leftX="260" bottomZ="80" lanes="5" columns="9">`（1 格=80，5 行 9 列），逐行 `<grid id="mvz2:grass" />`（水行用 `mvz2:water`）；
- **地图**（maps.xml）：`<map id="halloween" area="mvz2:halloween">` 关联区域 + `<stages>` 列出关卡顺序；地图上的**图钉**（pin 元素）带 `target_map_id` 跳转其他地图；
- 关卡与地图的对话触发：stages.xml 里 `<talk type="start|end|map" ... />`（对话本体在 `metas/talks/{章节}.xml`）。

### 9.5 解锁（unlocks.xml）

```xml
<group id="contraption.tnt">
    <conditions><condition required="mvz2:level.halloween_6" /></conditions>
</group>
```

器械侧引用：`<unlock><condition requiredGroups="mvz2:contraption.tnt" /></unlock>`。变体：`required`（单进度）/ `requiredGroups` / `requiredNotGroups`。系统功能（图鉴/商店/星之碎片）也是解锁组。

### 9.6 星之碎片能量（器械星之碎片能力的燃料）

```text
获取：每波按计数器给新刷敌人挂"碎片携带"Buff（每 6 只 1 个），击杀掉碎片（StarshardStageBehaviour.cs:21-44）
使用：玩家拾取碎片拿在手里 → 点可激发的器械 → 消耗 1 个碎片 + 器械 Evoke()
      （StarshardHeldItemBehaviour.cs:55-60；消耗恒定 1 个，无 XML 属性可调）
器械侧开关：instantEvoke（种下立即激发）/ no_evoke（不可激发）/ nocturnal（白天不能激发）
Evoke 本体：生成星光特效 + 调所有 IContraptionEvokeBehaviour.Evoke + POST_CONTRAPTION_EVOKE 回调
           （VanillaContraptionExt.cs:34-46）
```

器械要接星之碎片能力：**override `OnEvoke`**（三头/地雷都是这么写的）+ 确保没有 `no_evoke=true`。

## 10. 图鉴、碎片、本地化

### 10.1 图鉴（almanac.xml）

三层结构：`<tags>`（标签枚举）→ `<globalVariables>`（可复用取值）→ `<contraptions>/<enemies>/<artifacts>` 条目。

器械条目模板（almanac.xml:246-262）：

```xml
<entry id="mvz2:dispenser">
    <header><p>顶部说明文字</p></header>
    <properties><p>
        <![CDATA[ 伤害 <var id="mvz2:entity_damage" /> <ref=[contraptions]mvz2:tnt>TNT</ref> ]]>
    </p></properties>
    <flavor><p>风味文本</p></flavor>
</entry>
```

- `<var id="mvz2:entity_damage" />` 直接引用实体 XML 数值（全局变量在 almanac.xml:234-242 定义，如 `entity_health = property("mvz2:entity/maxHealth")`）；
- **不建图鉴条目也能玩**（只是图鉴看不到）。

### 10.2 碎片颜色（fragments.xml）

图鉴集齐后的"闪卡变色"：

```xml
<fragment name="dispenser">
    <colorKeys>
        <key hex="#4F4F4F" time="0.35" />   <!-- 采集进度 0~1 的颜色标 -->
        <key hex="#C3A26D" time="1" />
    </colorKeys>
</fragment>
```

缺条目 = 无害警告 `Resource not found: mvz2:X`，碎片颜色回退默认。

### 10.3 本地化（给新内容加显示名）

```text
目录：Assets/Localization/source/（模板 .pot + en-US/.po + .mo）
键格式：源文本 = XML 里的中文原文；上下文区分用途：
    msgctxt "entity.name"  msgid "颠倒炸弹"  msgstr "Reverse Bomb"
生成：Unity 菜单 MVZ2/Assets/Localization/Update General Translations（从 entities.xml 等读 Name 写入 pot）
填翻译：en-US/general.po 里给对应 msgctxt 填 msgstr
发布：MVZ2/Assets/Localization/Compress Langauge Pack → 压成 GameContent 的 builtin.bytes
```

**不做这步**：游戏里显示名为空/原文（英文环境），游戏功能不受影响。

## 11. 踩坑大全（高频事故与自救）

| # | 坑 | 症状 | 正确做法 |
|---|---|---|---|
| 1 | 每帧写 `entity.State` 的 AI 不做死亡早退 | 死亡动画不播 | UpdateAI 开头 `if (entity.IsDead) return;` |
| 2 | `FLIP_X` 直接 SetProperty | 无效（敌人模板 faction 行为每帧覆盖） | 用 `VanillaModifierPriorities.FORCE` 优先级 modifier；但它会连带改移动/啃食方向——纯镜像外观应改动画 K `SpriteRenderer.flipX` |
| 3 | 忘了移速 ×0.4 | 速度不对 | 实际速度 = `mvz2:speed` × `WALK_SPEED_FACTOR(0.4)`；改速度走事件驱动 + 固定 RandomEnemySpeedBuff |
| 4 | 护甲 `ignored="true"` 以为在吸伤 | 护甲血量是摆设 | 只有去掉 ignored 才走护甲减伤；`takenCrushDamage` 等属性另算 |
| 5 | 播 BGM 盖掉关卡原曲 | 音乐冲突 | `level.PlayMusic` 是全局唯一；叠加用 `loopVolume` 循环音效 |
| 6 | Addressables 条目 GUID/标签填错 | 模型 missing/紫黑格 | 三处名字逐字对齐（6.2）；改后重启 Unity 再构建 |
| 7 | 构建只花 1 分多钟 | 改动不生效 | 跳过了 Addressables 重建，重来 |
| 8 | `m_MaskInteraction` 语义错（=1 无遮罩不可见；=2 被 mask 裁） | 按部件用途选 0/2；复制谁就保持谁 |
| 9 | Buff 大小写不一致 | `Could not find the buff meta` | 三处名字逐字一致（5.1） |
| 10 | 手写 YAML 覆写数组引用类型错误 | 运行时静默失效（无日志） | `List<AnimatorElement>` 只能引用 AnimatorElement（114 组件），不是 Animator（95）；改 Addressables/YAML 前先关 Unity |
| 11 | 特殊敌人不做 notActiveEnemy | 阻止关卡清场 | 附属物类实体加 `notActiveEnemy=true` |
| 12 | 空中实体落地结算只靠接触回调 | 被重力板等外力按回时卡死 | 加 `IsOnGround` 兜底结算（与回调幂等） |
| 13 | 起跳帧接触回调误判落地 | 反复起跳/资源瞬间耗光 | 最小滞空时间（FrameTimer）内不算落地 |
| 14 | 模型组件遍历用 `transform.root` | 一个实例的状态扩散到全场 | 遍历根用 `Model.transform`（Model 挂在模型实例根） |
| 15 | 新实体不做 notActiveEnemy/not_target 被索敌 | 器械打附属物 | 附属物加 `notActiveEnemy`；不想被索敌加 `not_target`（检测器要放行用 `canDetectNoTarget=true`） |

## 12. 常用 API 速查表

```text
【生成】level.Spawn(id, position, spawner, spawnParams)      通用生成（spawnParams 可带以下键）
        grid.SpawnPlacedEntity(id, param)                    按格种放器械（对齐网格，不含冲突清理）
        entity.Spawn(id, pos, param)                         以实体为源的生成
        SpawnParams 常用键（SetProperty）：
          EngineEntityProps.FACTION                          阵营（0 玩家/1 僵尸）
          EngineEntityProps.GRAVITY                          重力倍率（1=正常下落）
          EngineEntityProps.DAMAGE / DAMAGE_MULTIPLIER       伤害覆写
【伤害】entity.Explode(center, radius, faction, dmg, effects) 范围爆炸（faction 决定敌我）
        entity.ExplodeAgainstFriendly(...)                    只伤同阵营
        collider.TakeDamage(dmg, effects, source)             定点伤害
        entity.PreTakeDamage(input, result)                   行为级伤害修改（SetAmount 可免疫/放大）
【检测】new SphereDetector(r){factionTarget=Any, mask=...}    球形；DetectEntities/DetectExists/DetectEntityWithTheLeast
        entity.DestroyConflictGridEntities()                  秒杀自身要占格上的冲突器械
        entity.DestroyConflictGridEntitiesOnLand()            挂 Buff：落地时自动执行上面的
【状态】entity.State / SetCasting / IsEvoked / GetColumn / GetLane / IsOnGround / Position / Velocity
【计时】TimerHelper.NewSecondTimer(sec) / timer.Run() / timer.Expired / timer.RunToExpiredOrNull()
【模型】entity.SetModelProperty(name, value)                  驱动 prefab 上的激活器/换图组件
        entity.SetDisplayScale(scale)                         显示缩放（爆炸膨胀等）
【阵营】entity.GetFaction() / IsHostileEntity() / IsFriendlyEntity()
        level.GetLeftFaction() / GetRightFaction()
【效果】InsulatedBuff.Apply(entity, seconds)                  各 Buff 的静态 Apply（刷新语义）
【星之碎片】entity.Evoke()                                    触发器械星之碎片能力（消耗 1 碎片）
        VanillaContraptionExt.Evoke → IContraptionEvokeBehaviour.OnEvoke
【音效】entity.PlaySound(VanillaSoundID.xxx)                  带 pitch/volume 重载
        level.AddLoopSoundEntity(id, entity.ID)               循环音效（挂实体）
【网格】level.GetEntityColumnX(column) / GetEntityLaneZ(lane)  格坐标基准
        level.GetEntityGridPosition(column, lane)             格标准位置（对齐用）
        entity.GetColumn() / GetLane()                        实体所在格
        entity.DestroyConflictGridEntities()                  秒杀占格冲突器械
        entity.DestroyConflictGridEntitiesOnLand()            挂 Buff：落地时自动执行
【星之碎片能量】StarshardHeldItemBehaviour（手持激发）        消耗恒定 1 个；开关 instantEvoke/no_evoke
```
